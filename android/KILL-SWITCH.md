# Kill-switch «Убить терминал» (task-2, owner: android-shell)

Спецификация для экрана «Диагностика» (вставка в docs/LOGS-ZEN.md §2,
п.3 «Кнопки» — правит logs-qa, этот файл — исходник формулировки).

## Точная строка для спеки (logs-qa, вставь как есть)

- «Убить терминал» → диалог-подтверждение («Завершит все shell/PTY-процессы
  в proot, несохранённое состояние терминалов потеряется») → выполняет
  `sh launch-dsh.sh kill-terminal` (имя подкоманды — контракт architect-proot;
  до её появления в скрипте кнопка скрыта: `status` не содержит маркер
  `terminal-killable`) → тост «Терминал остановлен» / «Не удалось (rc=N)» →
  строка-маркер `DshLog.keepalive(ctx, "terminal-kill requested")`
  (logcat `dsh-keepalive` + append `dsh.out.log`, формат LOGS-ZEN §25).

## Контракт со стороны shell (уже заложено / будет при появлении подкоманды)

1. Кнопка живёт в `DiagnosticsActivity` рядом с «Стереть логи»
   (id `diag_term_kill`, строка `diag_term_kill`).
2. Видимость — по capability-детекту, а не по версии: нет подкоманды —
   нет кнопки (нянек для устаревших скриптов не держим).
3. Никакого прямого `kill <pid>` из Java: только declared entry-point
   скрипта (selinux/toybox на прошивках режут самодеятельность).
4. Fail-closed: `kill-terminal` обязан быть идемпотентным (повторный вызов
   после убийства — rc=0, «already stopped»), иначе кнопка врёт.
5. Маркер пишется ДО вызова скрипта (факт намерения переживает даже
   падение самого килла и попадёт в следующий bugreport-zip).

## Границы

- PTY/терминальный UI — зона terminal-pro (task-7); здесь только аварийный
  выключатель процессов.
- Сам подкоманда `kill-terminal` и PID-учёт терминалов — зона architect-proot
  (launch-dsh.sh) по ADR-proot §D6; без неё спека не активируется (п.2).
